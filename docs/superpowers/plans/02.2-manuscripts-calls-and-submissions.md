# 02.2 Calls, catalogue and submissions: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. AGENTS.md also requires superpowers:test-driven-development, and the `expo` skills (`expo:expo-router`, `expo:expo-ui`) for screens.

**Goal:** Publications create calls; every signed-in account browses the catalogue (Open calls / Publications); writers send one manuscript version to several calls with PDF materials and see a per-call result with retry.

**Architecture:** Rules live in Postgres: RLS on every new table, `security definer` functions for every write (`save_call`, `publish_call`, `cancel_call`, `submit_manuscript`), and two `security_invoker` views for the catalogue. Material PDFs reuse the 02.1 upload function and private bucket. The app adds a publisher menu, the call editor (S-43), the catalogue (S-24) and a composer route (S-25 to S-27).

**Tech Stack:** Supabase (Postgres, pgTAP, Storage, Edge Functions on Deno), Expo SDK 58 with Expo Router, TypeScript, Jest (`jest-expo` for screens, `jest.gateway.config.js` for tests against the local stack).

**Spec:** module plan `2026-10-17-lisette-02-manuscripts.md` §02.2; `docs/product/requirements.md` (Multi-Publisher Submission Flow, Submission Requirements, Sharing Policy, Protection Policy, Publisher Discovery Catalogue); tables in `docs/superpowers/specs/2026-10-21-lisette-database-design.md` §6 and `lisette-schema.html`.

## Decisions from the 2026-11-11 discussion

- Catalogue: two tabs, Open calls (default) and Publications. Every signed-in account sees it (readers, writers, publications); only writers can send.
- Publication menu: Home · Discover · + · Calls · Profile. Discover shows the catalogue; Calls lists the publication's own calls. In 02.3, Submissions takes Profile's place and Profile moves to the top-right button, as for writers.
- Local seed: three approved publications, one of each kind, with fixed local-only logins and a few calls. No seeded writers or manuscripts: `owner_pdf_access` counts every object in the `manuscripts` bucket.
- Contact details: the email comes from sign-up (`private_contacts.contact_email`). The phone number entry screen (a private "Contact details" section on Profile) is **Alexia's**, not part of 02.2. Until it exists, the phone is set locally with SQL (Task 3 adds the command to the local-development notes). A submission copies both. If the phone is missing, the review step says so and Send stays disabled.
- Materials: synopsis and sample are **PDF files only** (same validation as manuscripts, no Word). The author introduction is a short text. Each call's five `req_*` flags decide what is required.
- One active submission per **work** and publication. A batch starts from one version, so one batch holds at most one call per publication. Different works can go to several calls of the same publication.
- On a new submission, the publication gets an in-app notification (`domain_events`). Email comes with 06.1.

## Defaults chosen here (change before implementing if wrong)

- A published call stays editable until cancelled. Submissions already sent keep their `accepted_policy` snapshot.
- The deadline picker chooses a date. `closes_at` is stored as the end of that day in the device's time zone.
- Call languages offered in the editor: `ro`, `en` (one constant; extend it when needed).
- The composer creates one `idempotency_key` per call and reuses it for every retry in that session. A failed submit stores nothing, so reuse is safe.
- Material PDFs are uploaded once per batch and the same storage path is referenced by each call's submission. An abandoned batch leaves orphan files (retention is undecided; no cleanup in 02.2).
- Reading material PDFs through the `manuscript-file` gateway comes with 02.3. Nobody needs to open them in 02.2.

## Global Constraints

- Tables, columns, types and limits come only from the database design and `lisette-schema.html`. Any change is recorded in both, and `lisette-schema.html` is republished as the artifact with a changelog entry.
- Migrations via `npx supabase migration new <topic>`. `npx supabase db reset` must rebuild cleanly. Functions read the caller from `auth.uid()` only, `set search_path = ''`.
- `export_my_data()` is redefined with `create or replace`. Start from the latest version (in `20261024160051_manuscript_versions.sql`) and keep every existing key.
- Limits: `calls.title` 1–200, `calls.description` ≤ 5000, `accepted_languages` at least one ISO 639-1 code, `submission_materials.body` ≤ 5000, PDF ≤ 20 MiB (20 971 520 bytes), phone `^\+[1-9][0-9]{6,14}$`.
- Rights declaration copy, verbatim: "I confirm that I wrote this manuscript, or have permission from all rights holders to submit it and share the selected material."
- Never say manuscripts are encrypted; never call the hash or device authentication proof of authorship; downloads cannot be recalled.
- Translations only inside existing groups (`submit`, `publisher`, `nav`, `manuscripts`, `errors`) in both `ro.json` and `en.json`; reuse the draft keys already there.
- Install packages with `npx expo install`; everything must keep running in Expo Go.
- Claude never commits. Each task ends at a checkpoint where the user commits.

## Review Focus

1. **A call closes or is cancelled while the writer is on the review step.** Only that call fails (`call_not_open`); the others are sent. Test: Task 2 `closed call rejects` and Task 4 `batch_retry_is_independent`.
2. **The connection drops after the server committed.** The result is Unknown; retrying with the same key returns the same submission, with no second row and no second event. Test: Task 2 `replay returns the same id` and Task 4 `unknown outcome resolves to the existing submission`.
3. **The writer ticks two calls of the same publication.** The second replaces the first in the selection; the server would reject it anyway. Test: Task 7 `toggleCall keeps one call per publication`.
4. **The publication edits or tightens a published call after submissions exist.** Existing submissions keep the requirements they accepted. Test: Task 2 `accepted_policy is a snapshot`.
5. **A publication is suspended after publishing calls.** Its calls disappear from Open calls and refuse submissions. Test: Task 1 `suspended publisher's calls are not open` and Task 2 `unapproved publisher rejects`.

### Task 1: Calls in the database

**Files:**
- Create: `supabase/migrations/<timestamp>_calls.sql` (`npx supabase migration new calls`)
- Test: `supabase/tests/database/calls_are_publisher_owned.test.sql`

**Interfaces:**
- Produces: tables `calls`, `call_genres` (columns exactly as in the schema).
- `call_is_open(c public.calls, at timestamptz default now()) returns boolean`: published, not cancelled, `opens_at <= at`, `closes_at` null or `> at`, and `can_receive_submissions(c.publisher_id)`.
- `save_call(call_id uuid, title text, description text, opens_at timestamptz, closes_at timestamptz, accepted_languages text[], req_full_manuscript boolean, req_synopsis boolean, req_sample boolean, req_genre boolean, req_author_intro boolean, genre_ids uuid[]) returns uuid`. A null `call_id` creates. Caller must be a `publishers` row (pending allowed). Replaces `call_genres`. Errors: `not_publisher` (42501), `not_owner` (42501), `call_cancelled`.
- `publish_call(call_id uuid) returns void`: sets `published_at` once. `cancel_call(call_id uuid) returns void`: sets `cancelled_at` once. Both owner-only.
- View `open_calls` (`security_invoker`): call columns plus `publisher_name`, `publisher_kind`, `sharing_policy`, `genre_ids uuid[]` (`'{}'` = any genre), only rows where `call_is_open`.
- View `catalogue_publishers` (`security_invoker`): approved publishers with `id, name, kind, intro, logo_path, genre_ids` (from `publisher_genres`), `open_call_count`, `languages text[]` (distinct over their open calls).
- RLS: `calls` select for `publisher_id = auth.uid()` or (published, not cancelled, `can_receive_submissions`). `call_genres` select where its call is visible. No insert/update/delete policies.

### Task 2: Submissions in the database

**Files:**
- Create: `supabase/migrations/<timestamp>_submissions.sql`
- Test: `supabase/tests/database/submit_manuscript_rules.test.sql`

**Interfaces:**
- Consumes: Task 1 tables and `call_is_open`; existing `can_receive_submissions`, `is_blocked`, `enqueue_event`.
- Produces: enums `submission_status`, `material_kind`; tables `submissions`, `submission_materials`, `submission_status_history` (schema columns; partial unique index `submissions_one_active` on `(work_id, publisher_id)` where status in `submitted, in_review, on_hold, selected`).
- `submission_block_reason(author uuid, work_id uuid, call_id uuid) returns text`, internal (revoked from clients). Returns null or one of `call_not_open`, `not_owner`, `blocked`, `duplicate_active`, `resubmission_not_allowed`. Shared by the next two functions.
- `submission_eligibility(version_id uuid, call_ids uuid[]) returns table (call_id uuid, reason text, submission_id uuid)`. `submission_id` is the existing active submission when the reason is `duplicate_active`.
- `submit_manuscript(call_id uuid, version_id uuid, genre_id uuid, materials jsonb, idempotency_key uuid, rights_declared boolean, contact_consent boolean) returns uuid`.
  - `materials` shape: `{"synopsis": "<storage path>", "sample": "<storage path>", "author_intro": "<text>"}`, keys optional.
  - Error messages (the client maps them): `not_signed_in`, `call_not_open`, `not_owner`, `blocked`, `duplicate_active`, `resubmission_not_allowed`, `missing_phone`, `missing_consent`, `missing_material`, `invalid_material`, `invalid_genre`.
  - Order:
    1. Return the existing id when the caller already used `idempotency_key`.
    2. Lock the call `for share` and check `call_is_open(call, clock_timestamp())`.
    3. Check the block reason, the phone in `private_contacts` and both consents.
    4. Check the requirements: required materials present; synopsis and sample paths must be objects in bucket `manuscripts` under `<auth.uid()>/materials/`; `req_genre` needs `genre_id`, which must be in `call_genres` when the call lists genres.
    5. Insert the submission with contacts copied and `accepted_policy = {"requirements": {"full_manuscript", "synopsis", "sample", "genre", "author_intro"}, "sharing_policy"}`, then the materials and the history row (`null → submitted`).
    6. `enqueue_event('submission_status_changed', id, 'submission_status_changed:' || id || ':submitted', array[publisher_id], '{in_app}')`.
    7. A `unique_violation` on the idempotency key returns the existing id; one on `submissions_one_active` raises `duplicate_active`. A `check_violation` raises `invalid_material`.
- RLS: select on `submissions` for `author_id = auth.uid() or publisher_id = auth.uid()`; materials and history through a visible submission; no write policies.
- `export_my_data()` gains `submissions` (as author, with materials and history) and `calls` (as publisher).
